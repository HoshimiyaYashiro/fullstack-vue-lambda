# Frontend Architecture & Guidelines - User Web (@repo/user-web)

This document defines the architectural guidelines, tech stack details, and directory organization for the **User Web** application.

---

## 1. Tech Stack Overview

| Category | Technology | Description |
| :--- | :--- | :--- |
| **Framework** | Vue 3 (Composition API, `<script setup>`) | Modern progressive UI framework |
| **Language** | TypeScript (Strict mode) | Strict type safety across components and composables |
| **Build Tool** | Vite 6 | Lightning-fast HMR and ESM bundling |
| **Atomic CSS** | UnoCSS (`presetWind3`, `presetAttributify`, `presetIcons`, `presetTypography`) | Instant on-demand atomic styling with Tailwind v3 compatibility |
| **Layouts** | `vite-plugin-vue-layouts-next` | File-system-based dynamic layout wrappers |
| **Internationalization** | Vue I18n (`vue-i18n`) + `@intlify/unplugin-vue-i18n` | Compiled message bundles supporting English (`en`) & Vietnamese (`vi`) |
| **Routing** | `unplugin-vue-router` | File-system-based strongly typed routing |
| **UI Library** | Naive UI + `@repo/ui` | Enterprise UI design system and shared component tokens |
| **Auto Imports** | `unplugin-auto-import` | Auto-imports Vue, Vue Router, Pinia, VueUse, Vue I18n, queries & stores |
| **Component Auto Imports** | `unplugin-vue-components` | Auto-resolves Naive UI, `@repo/ui` (`App*`), and feature components |
| **Server State / Cache** | TanStack Query (`@repo/api-client`) | Server data fetching, reactive caching, background sync |
| **Client State** | Pinia | Lightweight reactive client state management |
| **Cloud / Auth SDK** | AWS Amplify (`aws-amplify`) | Client SDK for AWS authentication and cloud services |
| **Compiler Macros** | Vue Macros (`vue-macros`) | Extended syntax sugar and reactivity macros for Vite |
| **Head Management** | `@unhead/vue` | Reactive document title, meta tags, and SEO tags |
| **Composables** | `@vueuse/core` | Essential reactive composition utilities |
| **Validation** | Zod (via `@repo/shared`) | Isomorphic runtime schema validation |
| **Linting & Formatting** | Biome (`@biomejs/biome`) | High-performance unified linter and formatter |
| **E2E Testing** | Playwright | Cross-browser end-to-end testing |

## 2. Directory Structure (Feature-Driven / Vertical Slice)

The source directory (`src/`) is structured into self-contained business features:

```
apps/user-web/
├── e2e/                       # Playwright end-to-end test suites
├── src/
│   ├── features/              # Vertical business features
│   │   ├── account/           # Account overview domain
│   │   │   ├── components/    # Feature-private components (AccountOverviewCard.vue)
│   │   │   ├── views/         # Feature view container (AccountOverviewView.vue)
│   │   │   └── index.ts       # Public API barrel export
│   │   ├── auth/              # Authentication domain
│   │   │   ├── queries/       # Auth mutation hooks (use-auth.ts)
│   │   │   └── index.ts       # Public API barrel export
│   │   └── profile/           # User profile domain
│   │       ├── components/    # Feature-private components (ProfileForm.vue)
│   │       ├── queries/       # Profile queries & mutations (use-profile.ts)
│   │       ├── views/         # Feature view container (ProfileView.vue)
│   │       └── index.ts       # Public API barrel export
│   ├── i18n/                  # Vue I18n instance configuration
│   │   └── index.ts
│   ├── layouts/               # Layout templates (vite-plugin-vue-layouts-next)
│   │   └── default.vue        # Standard customer shell layout with navbar and footer
│   ├── locales/               # Message translation dictionaries
│   │   ├── en.json            # English locale
│   │   └── vi.json            # Vietnamese locale
│   ├── pages/                 # Thin route adapters managed by unplugin-vue-router
│   │   ├── [...path].vue      # 404 Catch-all route
│   │   ├── index.vue          # Mounts AccountOverviewView from @/features/account
│   │   └── profile.vue        # Mounts ProfileView from @/features/profile
│   ├── queries/               # Global query exports & re-exports
│   │   └── index.ts
│   ├── router/                # Router initialization & typed router bindings
│   │   └── index.ts
│   ├── stores/                # Global Pinia stores (user.ts)
│   ├── App.vue                # Root application shell & AppConfigProvider
│   ├── main.ts                # Application bootstrap & plugin registration
│   ├── style.css              # Global styles & virtual:uno.css injection
│   ├── auto-imports.d.ts      # Auto-generated by unplugin-auto-import
│   ├── components.d.ts        # Auto-generated by unplugin-vue-components
│   └── typed-router.d.ts      # Auto-generated by unplugin-vue-router
├── playwright.config.ts       # Playwright E2E configuration
├── uno.config.ts              # UnoCSS configuration with presetWind3
├── vite.config.ts             # Vite build & plugin configuration
├── tsconfig.json              # TypeScript project configuration
└── package.json               # Package dependencies and scripts
```

## 3. Architectural Boundaries & Best Practices

### A. Feature Encapsulation & Public API
- All feature-specific logic, components, and queries live inside `src/features/<feature-name>/`.
- Always import from `@/features/<feature-name>` rather than reaching into private sub-directories.
- Feature-private components inside `src/features/<feature>/components/` are auto-registered by `unplugin-vue-components`.

### B. Thin Pages Pattern with `unplugin-vue-router`
- Pages inside `src/pages/` simply declare routing parameters and delegate UI rendering to views exported from `@/features/*`.
- Keep page components concise (< 15 lines) serving strictly as route adapters.

### C. Layouts via `vite-plugin-vue-layouts-next`
- Layout components reside in `src/layouts/`.
- Default layout is `src/layouts/default.vue`. Custom layouts can be assigned per-page using `<route lang="yaml">` route blocks.

### D. Styling with UnoCSS & Theme Tokens
- Use UnoCSS utility classes (`presetWind3`) for component layout and styling.
- Utilize CSS variables from `@repo/ui/styles` (`var(--color-primary)`, `var(--color-surface)`, etc.) via UnoCSS theme mapping (`bg-primary`, `text-primary`, `bg-surface`).
- Custom styles can leverage `@apply` directives enabled by `transformerDirectives()`.

### E. Internationalization (i18n)
- Localize all user-visible text using `$t('key')` in templates or `t('key')` via `useI18n()`.
- Maintain parity between `src/locales/en.json` and `src/locales/vi.json`.
- Do not hardcode user-facing strings in UI components.

### F. Auto-Imports Workflow
- Standard APIs (`ref`, `computed`, `watch`, `useRouter`, `useRoute`, `useI18n`, etc.) are imported automatically by `unplugin-auto-import`.
- Naive UI components, shared `@repo/ui` components (`App*`), and feature components are resolved automatically by `unplugin-vue-components`. Avoid manual imports for these symbols.

### G. Server State vs Client State
- Use TanStack Query (`@repo/api-client`) for any data originating from the Lambda backend.
- Reserve Pinia stores (`src/stores/`) for purely client-side temporary state (e.g., local preferences, session state).
