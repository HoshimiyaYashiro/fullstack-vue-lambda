# Frontend Architecture & Guidelines - Admin Web (@repo/admin-web)

This document defines the architectural guidelines, tech stack details, and directory organization for the **Admin Web** application.

---

## 1. Tech Stack Overview

| Category | Technology | Description |
| :--- | :--- | :--- |
| **Framework** | Vue 3 (Composition API, `<script setup>`) | Modern progressive UI framework |
| **Language** | TypeScript (Strict mode) | Strict type safety across components and composables |
| **Build Tool** | Vite | Lightning-fast HMR and ESM bundling |
| **Routing** | `unplugin-vue-router` | File-system-based typed routing |
| **UI Library** | Naive UI + `@repo/ui` | Enterprise UI design system |
| **Auto Imports** | `unplugin-auto-import` | Auto-imports Vue, Vue Router, Pinia, VueUse APIs |
| **Component Auto Imports** | `unplugin-vue-components` | Auto-resolves Naive UI components & local components |
| **Server State / Cache** | TanStack Query (`@repo/api-client`) | Server data fetching, reactive caching, background sync |
| **Client State** | Pinia | Lightweight local state management |
| **Validation** | Zod (via `@repo/shared`) | Isomorphic runtime schema validation |
| **Linting & Formatting** | Biome (`@biomejs/biome`) | Fast linter and formatter |
| **E2E Testing** | Playwright | End-to-end browser testing |

## 2. Directory Structure (Feature-Driven / Vertical Slice)

The source directory (`src/`) is structured into self-contained business features:

```
apps/admin-web/src/
├── assets/                    # Static assets, SVG logos, and global stylesheets
│   └── styles/
│       └── main.css
├── components/                # App-wide, cross-cutting UI components (auto-imported)
│   ├── AppHeader.vue
│   └── AppSidebar.vue
├── composables/               # App-wide composables (auto-imported)
├── features/                  # Vertical business features
│   ├── dashboard/             # Dashboard domain
│   │   ├── components/        # Feature-private components (DashboardMetrics.vue)
│   │   ├── queries/           # Feature TanStack Query hooks (use-admin-metrics.ts)
│   │   ├── views/             # Main view component (DashboardView.vue)
│   │   └── index.ts           # Public API barrel export
│   │
│   └── users/                 # User Management domain
│       ├── components/        # Feature-private components (UserTable.vue, UserFilterBar.vue)
│       ├── queries/           # Feature TanStack Query hooks (use-admin-users.ts)
│       ├── views/             # Main view component (UserListView.vue)
│       └── index.ts           # Public API barrel export
│
├── layouts/                   # Application layout wrappers
│   ├── AdminLayout.vue
│   └── BlankLayout.vue
│
├── pages/                     # Thin route adapters managed by unplugin-vue-router
│   ├── index.vue              # Mounts DashboardView from @/features/dashboard
│   ├── users.vue              # Mounts UserListView from @/features/users
│   └── [...path].vue          # 404 Catch-all route
│
├── queries/                   # Re-exports feature queries for backward compatibility
│   └── index.ts
├── router/                    # Vue Router instance setup
│   └── index.ts
├── stores/                    # Global Pinia stores (Session, Global UI state)
├── App.vue                    # Root component
├── main.ts                    # Application bootstrap
├── auto-imports.d.ts          # Auto-generated by unplugin-auto-import
├── components.d.ts            # Auto-generated by unplugin-vue-components
└── typed-router.d.ts          # Auto-generated by unplugin-vue-router
```

## 3. Architectural Boundaries & Best Practices

### A. Feature Encapsulation & Public API
- All code related to a business capability belongs in `src/features/<feature-name>/`.
- **Public API Rule**: External files (such as `src/pages/` or another feature) must **only** import from the feature's index file (`@/features/<feature-name>`). Never import deeply from another feature's internal folders.
- Components inside `src/features/<feature>/components/` are private to that feature.

### B. Thin Pages Pattern with `unplugin-vue-router`
- `src/pages/` is dedicated strictly to file-based routing.
- Keep page components minimal (typically < 10 lines): they serve as route adapters that mount the feature's primary view component.

### C. Auto-Imports Workflow
- Standard APIs (`ref`, `computed`, `watch`, `useRouter`, `useRoute`, etc.) are imported automatically by `unplugin-auto-import`.
- Naive UI components (`<n-card>`, `<n-button>`, `<n-data-table>`, etc.) and components in `src/components/` are resolved automatically by `unplugin-vue-components`.

### D. Server State via TanStack Query
- Collocate API query hooks in `src/features/<feature>/queries/`.
- Always declare strongly typed query keys to facilitate clean cache invalidation.
